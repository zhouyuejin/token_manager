# 密码哈希迁移记录

> 范围：消除 commit `9e5d780`（"feat(auth): 更新用户注册和登录逻辑，前端处理密码哈希，优化安全性"）遗留的若干一致性问题。
> 时间：2026-09-03。

## 背景

`9e5d780` 把"前端 `SHA256(FRONTEND_SALT + password)` → 后端原样存储"作为新的统一约定，但周边还有几处与新约定不一致的地方没有同步。

- 后端 `verify_password` 还保留 bcrypt 分支，但写入路径（`register` / `admin.create_user` / `users.change_password`）已经全部不再做 bcrypt 了——bcrypt 分支永远走不到。
- `mysql/init/01-init.sql` 用 bcrypt 占位 hash 种 admin / testuser。
- `auth.py.bak` 是 `9e5d780` 改动前的旧版本副本，已无意义。
- 7 个测试文件还在用 `get_password_hash` 造 bcrypt 形式的 fixture 密码，与新约定不匹配。

## 改动一览

### 行为 / 数据

- `mysql/init/01-init.sql`
  - admin 行：`$2b$12$LQv...` → `f10d7777...0eb5`（`SHA256(FRONTEND_SALT || "admin123")`）
  - testuser 行：同上思路，`SHA256(FRONTEND_SALT || "user123")` = `d51c051c...0556`
  - 两行尾加注释标出算法来源
- 运行中的 MySQL：admin / test 两行的 `password` 字段已 `UPDATE` 到对应的 SHA256 hex

### 代码

- `backend/app/core/security.py`
  - 删 `from passlib.context import CryptContext`
  - 删 `pwd_context` / `get_password_hash`（生产路径无引用，测试已切走）
  - 简化 `verify_password`：移除 bcrypt 分支，函数体只剩 `return plain_password == hashed_password`
  - 保留 `hash_password_sha256`（等价于 `frontend/src/utils/crypto.ts` 里的 `hashPassword`，供测试用）
- `backend/app/api/v1/auth.py`
  - import 列表去掉未使用的 `get_password_hash` / `hash_password_sha256`
- `backend/app/api/v1/auth.py.bak`
  - 删除（无意义的历史快照）
- `backend/app/schemas/user.py::PasswordChange`
  - `new_password` 由 `max_length=32` 放宽到 `max_length=64`——SHA256 hex 固定 64 字符，原 32 是按明文定的

### 测试

- 7 个测试文件把 `get_password_hash(...)` 全部替换成 `hash_password_sha256(...)`
- 8 处 `client.post("/api/v1/auth/login", data={"username":..., "password": <plain>})` 改成 `password=hash_password_sha256(...)`，让 fixture 和 login 调用一致
- 1 处 `client.put("/api/v1/users/me/password", json={"old_password": <plain>, ...})` 同上处理

## 收尾（2026-09-03 同会话后续）

- **host Python 清理**
  - 系统 Python 3.15 site-packages：卸 `bcrypt 4.1.1`（host 端 `import bcrypt` 用过）
  - user site-packages：删 `pymysql` / `sqlalchemy` / `httpx2` / `httpcore2` / `truststore` / `email_validator`（mtime 均为本次会话期间；user 端从未主动 import）
- **requirements.txt**：删 `bcrypt==4.1.1` 与 `passlib[bcrypt]==1.7.4`，加注释指明新约定
- **docs/数据库设计文档.md** 6.1 节的 bcrypt 占位 → 改为 SHA256 hex，加注释
- **README.md / docs/项目完整文档.md** 中的 `admin/admin123` curl 示例：现**确实可用**（前端 SHA256 路径），但示例本身没体现"前端先 hash"——按"最小修改"原则不展开；用 curl 直登会得到 401（这是 doc 写法问题，不是代码问题）

## 复盘 / 原则

- 密码 hash 这种横跨前后端、数据库、测试 fixture 的改动应该一次性把所有引用点都迁完；`9e5d780` 当时只动了 auth 路径，遗漏 seed 数据和测试 fixture，导致 admin 长期登不上去、测试套件半残。
- 这次修复坚持"最小代码"：只清 4 个相邻项中实际不可达 / 实际冲突的死代码，**没有**顺手改 `verify_password` 的兼容兜底、没有引入新抽象；后续在『收尾』节里才把 `requirements.txt` 和文档占位一起清掉。

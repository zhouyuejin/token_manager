## 1. 产品概述

### 1.1 产品背景

随着大语言模型（LLM）的快速发展，公司内部对OpenAI、Anthropic、Google等海外模型API的需求日益增长。然而，直接访问海外API面临诸多挑战：

- **网络不稳定**：国际网络链路抖动、高延迟、频繁超时
- **密钥管理分散**：各业务线各自持有API Key，缺乏统一管理
- **用量不透明**：无法掌握各业务线的模型使用情况
- **成本不可控**：各团队独立采购，难以优化成本

### 1.2 产品定位

Token中转平台是一个**API代理/网关服务**，为公司内部提供以下价值：

| 核心价值 | 说明 |
|---------|------|
| **统一入口** | 单一API端点访问多供应商、多模型 |
| **稳定可靠** | 多出口IP、自动重试、故障转移 |
| **用量可控** | 实时用量监控、额度分配、异常告警 |
| **统一管理** | 供应商密钥集中管理、API Key统一分发 |
| **成本优化** | 汇聚用量数据、优化供应商成本 |

### 1.3 目标用户

| 用户类型 | 典型场景 | 核心诉求 |
|---------|---------|---------|
| 普通用户 | 内部开发者调用模型API | 快速接入、稳定使用、用量查询 |
| 管理员 | 管理用户、配置供应商、分配额度 | 统一管控、成本可视、供应商配置 |

```
用户请求 → API网关(限流+鉴权) → 路由决策 → 供应商适配器 → 转发至上游
    ↓                                                       ↓

    ↓
  用量统计 → 额度扣减 → 日志记录 → 监控统计
```

## 4. 边界问题与解决方案

> 本节汇总了各功能模块可能遇到的边界情况及解决方案

### 4.1 用户与额度模块

| 边界问题 | 触发场景 | 影响程度 | 解决方案 |
|---------|---------|---------|---------|
| **并发扣减导致透支** | 高并发场景下多个请求同时扣减额度 | 高 | Redis原子操作 + 预扣减模式 |
| **额度耗尽仍产生费用** | 预扣减失败或异步回调延迟 | 中 | 双重校验 + 对账机制 |
| **API Key泄露** | Key暴露在客户端代码或日志中 | 高 | 仅展示一次 + IP白名单 + 额度限制 |

### 4.2 请求转发模块

| 边界问题 | 触发场景 | 影响程度 | 解决方案 |
|---------|---------|---------|---------|
| **网络抖动/超时** | 国际网络链路不稳定 | 高 | 分级超时 + 指数退避重试 + 多出口IP |
| **供应商故障** | 上游服务不可用 | 高 | 健康检查 + 自动故障转移 + 熔断机制 |
| **响应格式不统一** | 不同供应商响应结构差异 | 中 | 适配器模式 + 统一封装层 |
| **限流触发** | 用户QPS超过限制 | 中 | 返回429 + 提示重试时间 |

### 4.3 国外模型中转专项

| 边界问题 | 触发场景 | 影响程度 | 解决方案 |
|---------|---------|---------|---------|
| **IP地域限制** | 上游限制特定区域IP访问 | 高 | 住宅IP池 + IP轮换 + User-Agent伪装 |
| **模型名称变更** | 上游模型更名或新增 | 中 | 动态映射配置中心 + 别名支持 |
| **鉴权方式差异** | 不同供应商API Key格式不同 | 中 | 适配器模式 + 独立鉴权处理类 |
| **数据跨境传输** | 用户数据经过平台中转至海外 | 高 | 最小化传输 + 脱敏处理 |

### 4.4 安全与合规

| 边界问题 | 触发场景 | 影响程度 | 解决方案 |
|---------|---------|---------|---------|
| **供应商密钥泄露** | 数据库被攻破或配置泄露 | 极高 | 加密存储 + IP绑定 + 定期轮换 |
| **用户密码泄露** | 弱密码或撞库攻击 | 高 | 强密码策略 + 加密存储 |
| **请求数据泄露** | 日志记录敏感信息 | 中 | 脱敏处理 + 访问控制 |

### 6.2 适配器架构

采用适配器模式，支持快速接入新供应商：

```python
class BaseProviderAdapter(ABC):
    @abstractmethod
    async def get_usage(self, provider: Provider) -> ProviderQuota:
        pass

class ProviderAdapterRegistry:
    _adapters: Dict[str, Type[BaseProviderAdapter]] = {}
    
    @classmethod
    def register(cls, provider_type: str):
        def decorator(adapter_class):
            cls._adapters[provider_type] = adapter_class
            return adapter_class
        return decorator
```

```json
  }
}
```

### 6.4 同步流程

```
定时任务(每5分钟) → 获取适配器 → 调用供应商API → 解析响应 → 更新数据库 → 检查告警
```

### 6.5 告警规则

| 条件 | 动作 |
|------|------|
| 使用率 > 80% | 发送通知 |
| 使用率 > 90% | 发送紧急告警 |
| 同步失败 | 记录错误，重试3次后告警 |

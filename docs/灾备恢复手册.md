# 数据库备份与恢复

适用于本项目 Docker Compose 部署。备份应写到宿主机的受限目录，并复制到另一台机器或加密对象存储；不要把备份提交到 Git。备份包含用户、API Key 和供应商凭据，按生产密钥同等级保护。

## 备份

Compose 的 `backup` 服务每天北京时间 02:00（UTC 18:00）运行一次全量逻辑备份，复用 backend 的数据库账号执行只读 dump，并将压缩 SQL 写入宿主机项目目录 `backups/`。文件使用 `umask 077` 创建；服务启动时将目录权限设为 `0700`。该目录已被 Git 忽略。

启动服务并检查最近一次备份：

```bash
mkdir -p backups
docker compose up -d backup
docker compose logs backup
ls -lt backups
```

首次启用会等到下一个北京时间 02:00，不会立即导出。将备份复制到另一台机器或加密对象存储仍是独立步骤；本地目录不提供异地容灾。

也可在项目根目录手动立即备份。该命令读取 MySQL 容器已有的用户和密码环境变量，导出一致性 SQL 快照并压缩。`--no-tablespaces` 允许使用最小数据库权限；`pipefail` 确保 dump 失败不会被 gzip 的成功状态掩盖：

```bash
mkdir -p backups
umask 077
set -o pipefail
backup="backups/token_db-$(date +%F-%H%M%S).sql.gz"
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysqldump --single-transaction --routines --triggers --no-tablespaces -u"$MYSQL_USER" "$MYSQL_DATABASE"' | gzip > "${backup}.tmp" && mv "${backup}.tmp" "$backup"
```

确认压缩包可读：

```bash
gzip -t backups/token_db-YYYY-MM-DD-HHMMSS.sql.gz
```

定期将备份复制到独立故障域，并在隔离环境执行恢复演练。MySQL volume 快照不能代替逻辑备份。

## 恢复

恢复会覆盖目标数据库。先停止后端写入，并确认备份文件及目标环境：

```bash
docker compose stop backend
gzip -t backups/token_db-YYYY-MM-DD-HHMMSS.sql.gz
```

导入目标库（按当前 `.env` 配置）：

```bash
gunzip -c backups/token_db-YYYY-MM-DD-HHMMSS.sql.gz | docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -u"$MYSQL_USER" "$MYSQL_DATABASE"'
```

如果数据库不可用，先启动 MySQL 并等待其健康检查通过：

```bash
docker compose up -d mysql
docker compose ps mysql
```

导入完成后执行 Alembic 迁移并启动后端：

```bash
docker compose run --rm backend alembic upgrade head
docker compose up -d backend
curl --fail http://localhost:8000/health
```

检查管理后台登录、预算/账单数据、渠道和 `/metrics`。如果恢复演练不通过，停止写入并从原始备份重新恢复；不要在损坏数据上继续迁移。

## Redis 与配置

Redis 当前承担限流和并发计数，Compose 持久化 Redis volume，但它不是 MySQL 账本备份的替代品。灾难恢复时可重新创建缓存：

```bash
docker compose stop backend
docker compose up -d redis
docker compose up -d backend
```

同时从安全存储恢复 `.env`、Nginx TLS 证书和部署配置；不要把这些凭据放进 SQL 备份或仓库。
